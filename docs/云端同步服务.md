# 云端同步服务（cf-config-api）

> **这份文档是 Worker 在本仓库里的唯一记录。**
> 完整源码归档在**附录 A**，可直接整份复制去部署。
> **每次改动前后都要回来更新本文件** —— 否则这些接口约定、键名与踩过的坑会随上下文一起丢。

## 1. 拓扑

| 项 | 值 |
| --- | --- |
| Worker 名 | `cf-config-api` |
| 托管 | Cloudflare Workers，数据存 Cloudflare KV |
| 对外入口 | `https://www.998244353.best/api/*` —— 通过 **Worker Route** 挂在站点自己的域名下 |
| 为什么不用 workers.dev | 该子域在国内网络不通，所以前端一律走同域的 `/api/*` |
| KV binding | **`CF_CONFIG_KV`** —— 源码里是 `const KV = 'CF_CONFIG_KV'`，一律用 `env[KV]` 取值（写成 `env.CFG` 之类会得到 `undefined`，一调用就抛） |
| 源码 | **完整源码见附录 A**（2026-09-30 由仓库使用者提供，已核对并修好） |
| 回滚 | Dashboard → Workers & Pages → `cf-config-api` → **Deployments**，可一键回滚上一版本 |

前端侧的三条约定（`src/services/cloudProfile.js` 文件头有同样一段）：

- 网页版一律用相对路径 `/api/*`：浏览器视角是同源请求，**不需要 CORS**，也不会和 `COEP: require-corp`（本地 WASM 沙箱靠 SharedArrayBuffer 的硬前提）打架。
- 本地开发由 `vite.config.js` 的 `apiProxy` 经 `server.proxy` / `preview.proxy` 转发到 `https://www.998244353.best`。
- **Tauri 壳（桌面 / Android）走站点绝对地址** `https://www.998244353.best/api/*`。壳里的页面不在站点域下，而是来自自带的资源协议（Windows / Android 是 `http://tauri.localhost`，macOS / Linux / iOS 是 `tauri://localhost`），相对路径会被那个协议接住 —— 它不认识 `/api`，回一份 `index.html` 加状态 200，前端只能报 `badBody`（2026-10-09 在 Android 上实测到的症状）。
  绝对地址仍是**站点自己的域名**，所以「别写死 Worker 域名」那条规矩没有被破坏（要避开的始终是 workers.dev 子域，它国内不通）。
  代价是这趟请求变成跨源，**Worker 必须放行壳的来源**（见 `ALLOWED_ORIGINS`），否则会被 CORS 拦成 `unreachable`。`COEP: require-corp` 不挡这条路：跨源请求走的是 CORS 模式，CORS 过了即满足 COEP。

## 2. 身份验证模型

绑定身份用的是 **Codeforces handle** —— 不是 Cloudflare 用户名，Cloudflare 只是这个 Worker 的托管平台。所有面向用户的文案都必须说 Codeforces。

1. 前端 `POST /api/get-code {handle}`，服务端生成 `CF-XXXXXX`（取去掉短横的 UUID 前 6 位十六进制、转大写）存进 KV，TTL 600s。
2. 用户自己去 Codeforces → **Profile → Social** 一页，把验证码填进 **Last name** 并保存。
   （2026-10-11 加了一条可选捷径：装了 CC for Web 扩展、且它自报 `fill-code` 能力时，设置面板与齿轮菜单里会多一颗「在 Codeforces 上自动填写」，由扩展在那一页替用户填并保存 —— 全程在浏览器里，扩展**不读 cookie、不回传页面内容**。服务端这一侧**一字未改**：下面第 3 步照旧。协议见 HANDOFF 第 13 节。）
   （同日又加了一行**预检**：扩展自报 `cf-check` 能力时，取到码就先问一句「这个浏览器登的是不是你填的这个 handle」，把「没登录 / 登的是别人」提前说成一行提示，而不是让用户白点一次才看到失败文案。扩展**只回 `match` / `mismatch` / `not-logged-in` / `unknown` 四个枚举、绝不回用户名** —— handle 明文本来就是前端自己填的，所以这个回答里没有前端原本不知道的信息，也就不必新增任何「收集用户名」的声明。它只影响那行提示的措辞与颜色，**不参与鉴权**：第 3 步照旧。）
3. 服务端调公开 API `https://codeforces.com/api/user.info?handles=<handle>`，取 `result[0].lastName` 与 KV 里的码比对（两边都 `trim()` + `toUpperCase()`，所以大小写不敏感）。对得上就认为「能改这个公开资料的人 = 这个账号的主人」。

安全边界（必须知道）：

- `GET /api/config/<handle>` **公开可读、无任何鉴权** —— 云端配置的内容等于公开的。这正是 `cloudProfile.js` 的 `SYNC_KEYS` 刻意排除 `cp.judgeBases`（可能是内网判题服务器地址）的原因。
- 只有「写」需要证明身份。
- handle 一律按小写归一化（前端传 `he-jie`、Codeforces 规范名是 `He-Jie`，实测 `GET /api/config/he-jie` 可读到）。
  合法形状：`^[A-Za-z0-9_.-]{3,24}$`。

## 3. 接口契约

### POST `/api/get-code`

```
请求  { handle }
响应  200  { success: true, msg: "验证码已生成", handle, code: "CF-XXXXXX" }
失败  429  { success: false, msg: "取码过于频繁，请 10 分钟后再试" }
```

限制：同一 handle **10 分钟内最多 5 次**；**每取一枚新码会让上一枚立刻作废**。

### POST `/api/verify-save`

```
请求  { handle, data }
响应  200  { success: true, msg: "绑定成功", handle, updatedAt, token }
失败  400  { success: false, msg: "验证码已过期或未获取，请重新取码" }      // KV 里没有码
失败  400  { success: false, msg: '验证失败：当前 Last Name 为「CF-F4B40B」，与验证码不一致' }  // KV 有码但对不上
失败  502  { success: false, msg: "无法连接到 Codeforces，请稍后重试" }     // CF 接口挂了 / 该 handle 不存在
失败  400  { success: false, msg: "配置必须是 JSON 对象" | "配置项过多（上限 40）" | "非法键名：x" | "配置体积过大" }
```

`token` 是 2026-09-30 新增的设备令牌（第 8 节），前端存下来后可以走 `/api/save` 而不再取码。
**验证成功时会把码从 KV 删掉**（第 5 节第 1 条），所以「证明身份」与「写入」是同一个原子动作 —— 没有「只验证」的接口。

### POST `/api/save`（设备令牌写入）

```
请求  { handle, token, data }
响应  200  { success: true, msg: "已保存", handle, updatedAt }
失败  400  { success: false, msg: "缺少设备令牌" }
失败  401  { success: false, msg: "登录已失效，请重新验证 Codeforces 身份" }
```

### POST `/api/unbind`

```
请求  { handle }
```

**会删掉云端的 `config:<handle>`**（`msg` 是「已解绑，云端配置已删除」），且和 `verify-save` 一样要求一枚新鲜验证码。
**前端当前不调用它** —— 界面上的「解绑」已是纯本机操作（只清 `cp.cloudAccount`），见第 6 节。
（如果哪天要支持带令牌解绑，在这里加一条 `token` 分支即可；现在刻意没有，避免误删。）

### GET `/api/config/<handle>`

```
响应  200  { v, handle, updatedAt, data }
未保存 404  {"error":"未找到该用户的配置"}
```

这个 404 的 body **不是** `{ success }` 形状，前端按状态码判 `notFound`，不当错误抛。

### 通用

```
handle 不合法       400  { success: false, msg: "handle 不合法（3–24 位字母/数字/下划线/点/短横线）" }
非 POST 打到写接口  405  { success: false, msg: "方法不允许" }
请求体不是合法 JSON 400  { success: false, msg: "请求体不是合法 JSON" | "请求体过大" }
路径不认识          404  { success: false, msg: "未知接口" }
OPTIONS             204  （带 CORS 头——服务本地开发与 Tauri 壳这两个跨源来源）
```

## 4. KV 键

| 键 | 内容 | TTL |
| --- | --- | --- |
| `code:<handle>` | `{ code, count }` —— 验证码**与取码计数在同一个记录里** | 600s，每次成功发码重新计时 |
| `config:<handle>` | 配置信封 `{ v, handle, updatedAt, data }` | 永久（`/api/unbind` 会删它） |
| `tok:<token>` | → handle（设备令牌） | 一年，`TOKEN_TTL` 可配 |
| `tokidx:<handle>` | 该 handle 已签发的令牌数组，供吊销 | 同上 |

键名已由源码核对确认（2026-09-30）。

服务端**不校验键名语义**：`validateData()` 只看形状 —— 必须是对象 / 键数 ≤ 40 / 每个键名匹配 `^[A-Za-z0-9._-]{1,64}$` / 序列化后 ≤ 64KB。
「哪些键该同步」这份语义白名单完全由前端 `SYNC_KEYS` 负责，所以**增删同步项不必改 Worker**（改前端就行）。

## 5. 实测确认的行为（2026-09-30）

拿 handle `he-jie` 在线上实测，结论如下。这几条决定了方案 A 为什么非改后端不可，**且已由附录 A 的源码逐条核对确认**：

1. **验证成功即消费掉那枚码。** 同一枚码刚验证通过、远没到 TTL，紧接着再打一次 `verify-save` 就回「验证码已过期或未获取，请重新取码」。
   源码依据：验证通过后执行 `await env[KV].delete('code:' + handle)`。
   → 「登录后一段时间内免重新验证」这类**纯前端优化不可行**：登录那一步本身就把码用掉了，留不下可复用的东西。要免掉重复取码，只能由服务端另外签发一枚长期凭据 —— 即第 8 节的方案 A。
2. **每取一枚新码会让上一枚立刻作废。**
   源码依据：`issueCode()` 每次都 `put` 同一个 `code:<handle>` 键。
3. **同内容回写无副作用**：把 GET 拿到的 `data` 原样回写，键集合与每个值都不变，只有 `updatedAt` 变了。
4. 两句错误文案是有区分的：「与验证码不一致」= KV 里**有**码但对不上；「验证码已过期或未获取」= KV 里**根本没有**码。
   → 之前那次「明明验证码一样却说过期」，就是在页面上点过「上传本机设置」取了新码，把用户已填进 Codeforces 的那枚顶掉了。
5. 取码计数 `count` 存在 `code:<handle>` 记录里、每次发码刷新 TTL。所以频率窗口是「从最后一次成功发码起 600s」，被限流时不再写 KV（不会续期）。
   顺带：因为 `verify-save` 成功会 `delete` 这个键，**验证一次会顺手把计数清零**（正常用户察觉不到）。

## 6. 前端侧约定

`src/services/cloudProfile.js` 是云同步的唯一边界：`SYNC_KEYS` 白名单 + `collectProfile` / `applyProfile` + 四个接口封装。
（「本机在跟谁」那份存档 `cp.cloudActive` **不是同步内容、而是本机事实**，读写都在 `src/services/cloudEntry.js`，见 6.2。）

**只有白名单里的键会离开设备**（15 个）：`cp.editorSettings`、`cp.editorSettingsVersion`、`cp.shortcuts`、`cp.uiScale`、`cp.uiLocale`、`cp.panelPosition`、`cp.editorShare`、`cp.sidebarTab`、`cp.mdView`、`cp.timeLimitMs`、`cp.engine`、`cp.autoPreload`、`cp.cfPicker.autoInstall`、`cp.fileTemplates`、`cp.fileTemplates.enabled`。

`cp.fileTemplates` 是模板功能的**用户覆盖表**（`{ [语言]: 文本 }`，只存改过的语言，值都在 8000 字符内），`cp.fileTemplates.enabled` 是**总开关**（`'1'` / `'0'`）。两个键都**恒存**（空表就是 `{}`、默认写 `'1'`）：`applyProfile()` 只写云端存在的键，若本机从未自定义 / 从未关过、键缺席，「下载一份干净配置」就清不掉另一台设备的残留 —— 因此 `services/fileTemplates.js` 在模块加载时把两个键都先写回一次。

刻意不同步的键与理由：

- `cp.judgeBases` —— 可能是自建判题服务器地址，而云端配置**公开可读**，不该把内网地址送上去。
- `cp.testCases` —— 用户手写的测试用例，属于内容而非偏好，且体积大。
- `cp.localRuntime.clangReady` / `pythonReady` / `markdownReady` —— 是「**这台设备**有没有下载过」的事实，换台设备根本不成立，同步过去只会让新设备显示一个假的「已就绪」。

登录语义（2026-09-30 定稿）：

- **登录绝不写云端。** 云端已有配置 → 取码、用**云端原文**回写以证明身份（内容一字不改）→ 自动下载到本机 + 刷新；云端为空（404）→ 直接在本机认领 handle，不取码、不写任何东西。
- 唯一会覆盖云端的入口是已绑定态下的「上传本机设置」。
- 「解绑」是纯本机操作（只清 `cp.cloudAccount`），不发请求 —— 否则就会出现「点了没反应」（服务端要求新鲜验证码，失败只剩一行灰色小字）。**另外它其实很危险**：`/api/unbind` 会删掉云端那份配置。
- 设置分类「云端同步」在 `EditorSettingsPanel.vue` 的 `SECTIONS` 里排第 7（共 9 项，含桌面端独有的「工作区」；web 版过滤掉它后是 8 项），顺序是 工作区（仅桌面端）/ 外观 / 编辑器 / **模板** / 快捷键 / 评测 / **云端同步** / 应用 / 帮助。（`scripts/verify-ui.mjs` 的 B 步自 2026-10-01 起不再数分类个数，只逐项点开验行为，所以增删分类不用改脚本。）
- 该分类里「预下载本地运行环境」的开关写 `cp.autoPreload`（见 `src/services/runtimePreload.js`），**与绑定的三态 UI 分开放**：没账号的人也能先勾好。

### 6.1 公开性声明（2026-09-30 加）

因为 `GET /api/config/<handle>` 完全没有鉴权，**「上传」这个动作等价于「同意公开这份配置」**。这句话必须在用户按下按钮之前就看得见，否则他会以为上传只是「备份到自己账号下」。所以同一份声明铺在四处：

| 位置 | 形态 |
| --- | --- |
| 设置页「云端同步」 | `EditorSettingsPanel.vue` 里三态 UI 正下方一条 `.setting-group__note`，文案 key 是 `settings.cloud.publicNotice`（中英双份） |
| `guide.html` §11 常见问题 | h3「上传到云端的设置是公开的吗？」，排在「数据存在哪里？」之后 |
| `guide.en.html` §11 | 同一条，h3「Are cloud-synced settings public?」 |
| `docs/使用手册.md` | 末尾「附：关于云端配置的公开性」（**故意不编号**，这份文档的职责是只回答三个问题） |

声明里承诺的入口是「站点网址 + Codeforces 用户名」，形如 `https://www.998244353.best/he-jie`。

**应用内还有一条并列入口（2026-10-06 加）：设置 › 云端同步 › 填用户名点「导入」。** 起因是装成 PWA（独立窗口）后没有地址栏，走不了 `/<handle>` 那条路。按钮与「登录」并排，但语义完全不同：**导入只是 `fetchCloudProfile(handle)`**，不取码、不写 `cp.cloudAccount` / `cp.cloudToken`、不建立任何绑定；实现上把用户名塞进 `cloudApplyHandle`，复用地址栏那条「套用云端配置？」确认弹窗与 `confirmCloudApply()`（`fetchCloudProfile` → `adoptCloudProfile` → reload）。文案 key 是 `settings.cloud.import` / `settings.cloud.importTitle`（中英双份）。同一条路以后也解释成「导入 ≠ 登录」。

**同一批改动还补了反方向的一步（2026-10-06）：本机认下某个 handle 之后，把 `/<handle>` 写进地址栏。** 之前只有「打开别人的链接」这一个方向 —— 地址是别人给的，本站只负责不抹掉；现在本机自己在**导入 / 上传 / 登录 / 下载到本机**四条路成功之后（`cloudEntry.js` 的 `writeCloudEntryPath`），也会把 `/<handle>` 写上去，地址栏从此就是「我现在用的是谁的配置」，可收藏、可分享。三个要点：
- **用 `replaceState` 不用 `pushState`**：这不是跳转，多一条历史记录会让返回键把地址退回根路径、与眼前已经生效的配置对不上。
- **顺手打上 `cpCloudEntry` 记号**：地址是自己写上去的，刷新不该再问一次「要不要套用」——否则上传完一刷新，界面会问「要把你自己的配置套到你自己身上吗」。记号仍是那条「跟着历史条目走、不落 storage」的规矩。
- **带点号的 handle 直接放弃**：`HANDLE_PATH` / vercel 的 rewrite 都不认点号（会和 `guide.html` 这类静态资源撞车），宁可地址留在根路径，也不写一条刷新就 404 的链接。
- 上传两处在各自成功分支里直接调用；导入 / 登录 / 下载走 `adoptCloudProfile(data, handle)` 新增的第二个参数（写在 `applyProfile` 成功之后、那次 reload 之前，晚了就写不进去）。**「登录只下不传」的语义没变**，这里只是多改一次地址。

**这条入口已落地**（2026-09-30）：`vercel.json` 里 `/:handle([A-Za-z0-9_-]+)` 重写到 `index.html`；前端启动时读 `location.pathname`（`src/services/cloudEntry.js`），认出 handle 后把设置页切到「云端同步」并弹一次确认。点「套用」走的是与「下载到本机」同一条路（`fetchCloudProfile` → `adoptCloudProfile` → 刷新），但**不写 `cp.cloudAccount` / `cp.cloudToken`** —— 链接谁都能构造，套用它不该把这台设备变成那个账号的登录态。云端**没有**这份配置时（`GET /api/config/<handle>` 回 404）不走这条路：设置页不打开，地址抹回根路径，只弹一句「这个用户名还没有保存过配置」（2026-10-01）。

云端确实存着这份配置时，地址栏**保留** `/<handle>`，不抹回根路径：这条链接的含义就是「这个地址 = 这套配置」，抹掉之后想再打开一次、想复制给别人都得重新翻链接。代价是刷新（含套用成功后那次 reload）都会再看到同一段路径，所以用一个「这个条目已经答过了」的标记挡住重复追问 —— 标记写在 **`history.state`** 上（`cpCloudEntry` 键），随历史条目走、刷新后仍在、不落任何 storage，因此也不需要清理逻辑；换个新页签打开会照常再问一次。反过来，云端没有这份配置时地址会被直接抹回根路径 —— 没有可套用的东西，留着这条路径只会误导（2026-10-01）。**另外（2026-10-10 加）：地址里那位正好就是本机在跟的那位时不再问、也不打开设置页，直接按 6.2 对齐。**

`/<handle>` 之所以能和静态资源区分开，靠的是「**单段 + 不带点号**」：`guide.html` / `sw.js` / `robots.txt` / `manifest.webmanifest` 都带点号，`/assets/…` `/wasm/…` `/md/…` 都是多段 —— Vercel 的 rewrite 与前端那条正则用的是同一条规则。Service Worker 侧也照应了：`/<handle>` 的导航按自己的 URL 回填缓存（`src/sw.js`），离线再打开同一条链接仍能命中。

### 6.2 本机在跟谁（2026-10-10 加）

**要解决的问题**：6.1 那条「地址 = 这套配置」只活在当前页签里。关掉页签、第二天打开站点根路径，什么都没有发生 —— 用户得自己再走一遍导入 / 登录 / 翻出收藏的那条链接。

**做法**：本机认下某个 handle 时顺手落一份存档 `cp.cloudActive = { handle, updatedAt }`（`updatedAt` = **已套用过的那一版**云端的更新时间，空串 = 不知道），启动时地址里没有 handle 就拿它去对齐一遍。这就是「下次打开网站直接用它那一套」，不弹任何确认。

- **写入点与本机认下 handle 的四处一致**（也就是 `writeCloudEntryPath` 的四处）：上传两处在各自成功分支里直接调 `writeActiveProfile(handle, result.updatedAt)`；导入 / 登录 / 下载到本机（以及套用别人的 `/<handle>` 之后）走 `adoptCloudProfile(data, handle, updatedAt)`。**解绑删掉它**（`forgetActiveProfile`）—— 留着的话，下次打开站点会把刚解绑那位的配置又自动套回来，那是「解绑」最不该有的后果。
- **只认「云端版本变过」**：存档里的 `updatedAt` 与云端相同则一个字节都不写。少了这道闸门，每次打开站点都会覆盖本机一次（本机的临时改动静默消失），而且会「套用 → 刷新 → 又套用」转不出去 —— 那次 reload 是无条件的。云端换了新版本才对齐，等于始终把云端当目标。
  （登录那一步要记**回写后**的 `updatedAt`（响应里的那个），不是读到的旧值：`verify-save` 会把服务端的 `updatedAt` 顶成此刻，而云端现在存着的就是这一版。账号行上显示的时间仍然是旧值 —— 那两处口径不同是刻意的，见 `EditorSettingsPanel.vue` 里 `appliedVersion` 那段注释。）
- **不开设置页、不弹任何确认**；**地址栏会跟着走到 `/<handle>`（2026-10-10 加）**：对齐时若当前是「网页版的站点根路径」且云端确实有这份配置，就把 `/<handle>` 写进地址（`writeCloudEntryPath`，replaceState）—— 此后它就是那条可收藏、可分享的链接，与四条入口共用「地址 = 这套配置」这个语义。两道闸门缺一不可：
  - **只在 `IS_WEB` 且当前是站点根路径时写**（`cloudEntry.js` 的 `isSiteRoot()`）。壳端的页面来自 `tauri://localhost` / `http://tauri.localhost`，把地址改成 `/<handle>` 等于让壳的资源协议去找一个不存在的文件（一刷新就白屏），而壳里本来没有地址栏 —— 写了只有坏处；`guide.html` / `privacy.html` 那类静态页同理（replaceState 不跳转，但一刷新就跑到 IDE 去了）。
  - **只在 `fetchCloudProfile` 成功时写**：探测失败 / 404 时地址一动不动，否则会写出一条一刷新就只剩「还没保存过配置」的地址。
  - 这一行还必须排在 `applyCloudProfile` **之前** —— 那一步会 reload，排在后面根本执行不到。
- **地址里正好是本机在跟的那位时不问，直接对齐**；地址里是**别人**时行为不变（仍然弹一次「要不要套用」）。
- **404 / 离线一律静默**：什么都不做、存档留着 —— 这一刻云端没有不代表以后没有，删掉存档反而会让「另一台设备再传一次」永远同步不过来。
- **不进 `SYNC_KEYS`**：它是「**这台设备**在跟谁」的事实，同步过去等于让另一台设备自动套用一份它从没认领过的配置。
- **已知的边界（要加出口时看这里）**：非绑定的「在跟谁」（只导入过一份公开配置）在界面上**没有任何显示与出口** —— 设置页只在绑定态显示账号行，所以想停掉只能导入 / 登录另一位 handle，或者清站点数据。要加「停止自动套用」，得先定放哪一行（未绑定态那行输入框旁边最自然）以及要不要新文案（中英两份，`settings.cloud.*`）。

## 7. 前端侧令牌接线（已落地）

对应第 8 节的服务端改动，前端（`src/services/cloudProfile.js` + `EditorSettingsPanel.vue`）已接好：

- `cp.cloudToken` 存本机设备令牌，**不在 `SYNC_KEYS` 里** —— 令牌是每台设备各自的，同步过去等于把别的设备的写入权搬过来。
- `/api/verify-save` 成功时（登录与上传两条路径）把响应里的 `token` 落进 `cp.cloudToken`。
- 已绑定态点「上传本机设置」：本机有令牌就直接打 `/api/save`（不取码、不动 Codeforces）；没有令牌才退回取码流程。
- `/api/save` 回 **401** 时清掉本机令牌、`cloudCodeMode` 切回 `upload` 并自动取一枚码，面板恢复成验证码输入态，同时用一行提示（`settings.cloud.tokenExpired`）说明为什么突然又要验证码。非 401 的失败按原有错误分类显示。
- 「解绑」顺带清掉 `cp.cloudToken`（令牌跟着 handle 走，换绑别的 handle 不该带过去）。
- `postJson` 在失败分支会带上 HTTP `status`：调用方要区分「令牌不被承认（401，清令牌退取码）」与「请求内容不合法（400，原样报错）」，只看 `msg` 会误判。

## 8. 方案 A（设备令牌）设计说明

**要解决的问题**：`/verify-save` 是唯一写入路径，而它验证成功就删码（第 5 节第 1 条）。于是每写一次配置，用户都得重去 Codeforces 改一遍 Last name。

**做法**：验证成功时顺手签发一枚长期令牌，之后写入只带令牌。
`tok:<token>` → handle；`tokidx:<handle>` 记录已签发的令牌以便吊销。令牌是 `crypto.randomUUID()` 生成的 122 bit 随机串，不携带用户信息，只换来「能写这一个 handle 的配置」，且随时可吊销。

相对原文件一共四处改动，**都已并入附录 A 的完整源码**（这里不再重复贴代码，免得两处各自漂移）：

| # | 位置 | 改动 |
| --- | --- | --- |
| 1 | 文件顶部 | 新增 `TOKEN_TTL` / `kvOf` / `tokenOptions` / `readTokenIndex` / `issueToken` / `revokeTokens` |
| 2 | `/api/verify-save` 成功分支 | 写配置之后 `await issueToken(...)`，并把 `token` 放进响应 |
| 3 | 路由器 | 新增 `POST /api/save` 分支与其处理函数 `saveWithToken()` |
| 4 | `/api/unbind` | 删配置之前先 `await revokeTokens(...)`，一次废掉该 handle 的所有设备令牌 |

## 附录 A · Worker 完整源码（`cf-config-api`）

> 这是**改完并修好**的版本（含 2026-09-30 的设备令牌），整份替换即可。
> 相对仓库使用者提供的原始粘贴稿，修了 4 处 —— 其中前 3 处不修必定跑不起来：
>
> 1. `kvOf` 原本写成 `env.CFG`（不存在），改为 `env[KV]`；
> 2. `CF_API` 原本是 `'` + 反引号 + `https://...`（反引号被当成字符串内容），去掉反引号；
> 3. `ALLOWED_ORIGINS` 两条同样混进了反引号，去掉；
> 4. 补齐令牌接线（`verify-save` 签发、新增 `/api/save`、`unbind` 吊销），原稿只加了助手函数。

```js
/**
 * cf-config-api —— 站点云端配置后端（Cloudflare Worker）
 *
 * 路由：绑定 www.998244353.best/api/*
 * 只接管 /api/ 下的请求，站点其余路径完全不经过本 Worker。
 *
 * 接口：
 *   POST /api/get-code      { handle }               -> { success, code }
 *   POST /api/verify-save   { handle, data }         -> { success, token }
 *   POST /api/save          { handle, token, data }  -> { success }   ← 2026-09-30 新增
 *   POST /api/unbind        { handle }               -> { success }
 *   GET  /api/config/:handle                         -> { v, handle, updatedAt, data } | 404
 *
 * KV 键（绑定变量名必须是 CF_CONFIG_KV）：
 *   code:<handle>     取码记录 { code, count }，TTL 600s —— 一次写入同时发码与计数
 *   config:<handle>   已保存的配置信封，永久
 *   tok:<token>       设备令牌 -> handle，TTL 一年                     ← 2026-09-30 新增
 *   tokidx:<handle>   该 handle 已签发的令牌数组，供吊销                ← 2026-09-30 新增
 *
 * 设计取舍：服务端只校验配置的「形状」（体积/键数/键名字符），
 * 不硬编码键名白名单 —— 语义白名单由前端负责，这样以后增删同步项不必改 Worker。
 */

const KV = 'CF_CONFIG_KV'

const HANDLE_RE = /^[A-Za-z0-9_.-]{3,24}$/
const KEY_RE = /^[A-Za-z0-9._-]{1,64}$/
const MAX_BODY_BYTES = 64 * 1024
const MAX_KEYS = 40

const CODE_TTL = 600   // 验证码有效期（秒）
const CODE_MAX = 5     // 同一 handle 在窗口内的取码上限
const PROFILE_VERSION = 1

const CF_API = 'https://codeforces.com/api/user.info?handles='

/** 同源部署下 CORS 只服务于两类跨源来源：本地 dev server 与 Tauri 壳
    （壳的协议来源见 docs/云端同步服务.md 第 1 节；macOS/Linux/iOS 是自定义协议，
    所以三种形态都列出，多列一条没有副作用） */
const ALLOWED_ORIGINS = new Set([
  'https://www.998244353.best',
  'http://localhost:5199',
  'http://tauri.localhost',   // Tauri 壳：Windows / Android 默认协议来源
  'https://tauri.localhost',  // 同上，useHttpsScheme = true 时
  'tauri://localhost',        // Tauri 壳：macOS / Linux / iOS 默认协议来源
])

/* ---- 设备令牌（2026-09-30 新增）------------------------------------------
   起因：/verify-save 是唯一的写入路径，而它在验证成功时会把验证码从 KV 删掉
   （实测：同一枚码紧接着再打一次就报「验证码已过期或未获取」）。
   于是每写一次配置，都要让用户重去 Codeforces 改一遍 Last name。

   做法：验证成功时顺手签发一枚长期令牌，之后写入只带令牌。
     tok:<token>     → handle
     tokidx:<handle> → 该 handle 已签发的令牌，解绑时逐个吊销
   令牌是 crypto.randomUUID() 生成的 122 bit 随机串，不携带用户信息；
   它只换来「能写这一个 handle 的配置」，且随时可吊销。 */

const TOKEN_TTL = 31536000 // 秒，一年；填 0 表示永不过期

// 只在这一处引用 KV binding —— 名字必须与 wrangler.toml 里 kv_namespaces[].binding 一致
const kvOf = (env) => env[KV]

const tokenOptions = () => (TOKEN_TTL > 0 ? { expirationTtl: TOKEN_TTL } : undefined)

async function readTokenIndex(kv, handle) {
  try {
    const raw = await kv.get(`tokidx:${handle}`)
    if (!raw) return []
    const parsed = JSON.parse(raw)
    return Array.isArray(parsed) ? parsed : []
  } catch {
    return [] // 索引坏了就当没有：最坏是旧令牌吊销不掉，不影响新令牌签发
  }
}

async function issueToken(kv, handle) {
  const token = crypto.randomUUID().replace(/-/g, '')
  await kv.put(`tok:${token}`, handle, tokenOptions())
  const tokens = await readTokenIndex(kv, handle)
  tokens.push(token)
  await kv.put(`tokidx:${handle}`, JSON.stringify(tokens), tokenOptions())
  return token
}

/** 吊销该 handle 的全部令牌。相当于「让所有设备重新验证一次」 */
async function revokeTokens(kv, handle) {
  const tokens = await readTokenIndex(kv, handle)
  await Promise.all(tokens.map((t) => kv.delete(`tok:${t}`)))
  await kv.delete(`tokidx:${handle}`)
}

/* ---------------- 小工具 ---------------- */

function corsHeaders(request) {
  const origin = request.headers.get('Origin')
  const h = { Vary: 'Origin' }
  if (origin && ALLOWED_ORIGINS.has(origin)) {
    h['Access-Control-Allow-Origin'] = origin
    h['Access-Control-Allow-Methods'] = 'GET, POST, OPTIONS'
    h['Access-Control-Allow-Headers'] = 'Content-Type'
  }
  return h
}

function json(request, body, status = 200) {
  return new Response(JSON.stringify(body), {
    status,
    headers: {
      'Content-Type': 'application/json; charset=utf-8',
      'Cache-Control': 'no-store',
      ...corsHeaders(request),
    },
  })
}

const ok = (request, msg, extra = {}) => json(request, { success: true, msg, ...extra })
const fail = (request, msg, status = 400) => json(request, { success: false, msg }, status)

function normalizeHandle(raw) {
  if (typeof raw !== 'string') return null
  const h = raw.trim().toLowerCase()
  return HANDLE_RE.test(h) ? h : null
}

async function readJson(request) {
  const text = await request.text()
  if (text.length > MAX_BODY_BYTES) throw new Error('too-large')
  const parsed = JSON.parse(text)
  if (!parsed || typeof parsed !== 'object' || Array.isArray(parsed)) throw new Error('bad-body')
  return parsed
}

/** 只防滥用，不认键名语义；返回错误文案或 null */
function validateData(data) {
  if (!data || typeof data !== 'object' || Array.isArray(data)) return '配置必须是 JSON 对象'
  const keys = Object.keys(data)
  if (keys.length > MAX_KEYS) return `配置项过多（上限 ${MAX_KEYS}）`
  for (const k of keys) {
    if (!KEY_RE.test(k)) return `非法键名：${k}`
  }
  if (JSON.stringify(data).length > MAX_BODY_BYTES) return '配置体积过大'
  return null
}

async function fetchCfLastName(handle) {
  const res = await fetch(CF_API + encodeURIComponent(handle), {
    headers: { 'User-Agent': '998244353-best/1.0' },
  })
  if (!res.ok) throw new Error('cf-http-' + res.status)
  const body = await res.json()
  if (body.status !== 'OK' || !Array.isArray(body.result) || !body.result.length) {
    throw new Error('cf-status')
  }
  return body.result[0].lastName || ''
}

/** 发码：整个流程只写 KV 一次（读旧记录 -> 计数+1 -> 写回） */
async function issueCode(env, handle) {
  const key = `code:${handle}`
  const prev = await env[KV].get(key, 'json')
  const count = (prev && typeof prev.count === 'number' ? prev.count : 0) + 1
  if (count > CODE_MAX) return { limited: true }

  const code = 'CF-' + crypto.randomUUID().replace(/-/g, '').slice(0, 6).toUpperCase()
  await env[KV].put(key, JSON.stringify({ code, count }), { expirationTtl: CODE_TTL })
  return { code }
}

/**
 * 用设备令牌写入，跳过验证码。
 * 这是方案 A 的核心：一次验证换长期写入权，用户不必再碰 Codeforces。
 */
async function saveWithToken(request, env, handle, payload) {
  const token = typeof payload.token === 'string' ? payload.token.trim() : ''
  if (!token) return fail(request, '缺少设备令牌')

  const kv = kvOf(env)
  const owner = await kv.get(`tok:${token}`)
  // 令牌不存在 / 已过 TTL / 被吊销 / 属于别的 handle —— 一律当成「登录已失效」
  if (owner !== handle) {
    return fail(request, '登录已失效，请重新验证 Codeforces 身份', 401)
  }

  const invalid = validateData(payload.data)
  if (invalid) return fail(request, invalid)

  const updatedAt = new Date().toISOString()
  await kv.put(
    `config:${handle}`,
    JSON.stringify({ v: PROFILE_VERSION, handle, updatedAt, data: payload.data }),
  )
  return ok(request, '已保存', { handle, updatedAt })
}

/* ---------------- 入口 ---------------- */

export default {
  async fetch(request, env) {
    const url = new URL(request.url)
    const path = url.pathname.replace(/\/+$/, '') || '/'
    const method = request.method.toUpperCase()

    if (method === 'OPTIONS') {
      return new Response(null, { status: 204, headers: corsHeaders(request) })
    }

    // GET /api/config/:handle —— 公开读取，免登录
    const m = /^\/api\/config\/(.+)$/.exec(path)
    if (method === 'GET' && m) {
      const handle = normalizeHandle(decodeURIComponent(m[1]))
      if (!handle) return fail(request, 'handle 不合法')
      const stored = await env[KV].get(`config:${handle}`, 'json')
      if (!stored) return json(request, { error: '未找到该用户的配置' }, 404)
      return json(request, stored)
    }

    if (method !== 'POST') return fail(request, '方法不允许', 405)

    let payload
    try {
      payload = await readJson(request)
    } catch (err) {
      return fail(request, err.message === 'too-large' ? '请求体过大' : '请求体不是合法 JSON')
    }

    const handle = normalizeHandle(payload.handle)
    if (!handle) return fail(request, 'handle 不合法（3–24 位字母/数字/下划线/点/短横线）')

    // POST /api/get-code
    if (path === '/api/get-code') {
      const { limited, code } = await issueCode(env, handle)
      if (limited) {
        return fail(request, `取码过于频繁，请 ${Math.round(CODE_TTL / 60)} 分钟后再试`, 429)
      }
      return ok(request, '验证码已生成', { handle, code })
    }

    // POST /api/save —— 用设备令牌写入，跳过验证码（2026-09-30 新增）
    if (path === '/api/save') {
      return saveWithToken(request, env, handle, payload)
    }

    // POST /api/verify-save | /api/unbind —— 两者都需要一次有效的改名验证
    if (path === '/api/verify-save' || path === '/api/unbind') {
      const record = await env[KV].get(`code:${handle}`, 'json')
      if (!record || !record.code) return fail(request, '验证码已过期或未获取，请重新取码')

      let lastName
      try {
        lastName = await fetchCfLastName(handle)
      } catch {
        return fail(request, '无法连接到 Codeforces，请稍后重试', 502)
      }
      if (lastName.trim().toUpperCase() !== record.code) {
        return fail(request, `验证失败：当前 Last Name 为「${lastName || '（空）'}」，与验证码不一致`)
      }

      await env[KV].delete(`code:${handle}`)

      if (path === '/api/unbind') {
        await revokeTokens(kvOf(env), handle)   // 2026-09-30 新增：一次废掉该 handle 的所有设备令牌
        await env[KV].delete(`config:${handle}`)
        return ok(request, '已解绑，云端配置已删除')
      }

      const invalid = validateData(payload.data)
      if (invalid) return fail(request, invalid)

      const updatedAt = new Date().toISOString()
      await env[KV].put(
        `config:${handle}`,
        JSON.stringify({ v: PROFILE_VERSION, handle, updatedAt, data: payload.data }),
      )
      const token = await issueToken(kvOf(env), handle)   // 2026-09-30 新增
      return ok(request, '绑定成功', { handle, updatedAt, token })
    }

    return fail(request, '未知接口', 404)
  },
}
```
