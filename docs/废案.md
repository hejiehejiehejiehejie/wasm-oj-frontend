# 废案

明确不做、或无限期搁置的方案。**这不是待办清单**，别再照它派活；要重启其中任何一条，先找用户确认口径。

每条只写三件事：为什么停、停在哪、还剩什么没做。**已经落地的实现照旧留在仓库里**，删掉等于重做一遍。

## 1. 桌面端（Tauri 壳）· 2026-10-19 冻结

**口径**：macOS / Windows / Linux 三个桌面壳都不再推进。`src-tauri/`、`services/engines/native.js`、`export_*` 那几条 Rust 命令**全部保留、不删**——它们已经能跑，留着不碍事。**网页版与安卓壳不受影响**，两者与桌面端没有共用代码路径以外的耦合。

**为什么停**：网页版（含 PWA 离线）已经覆盖了实际使用场景；桌面壳要背的是一条独立的发布线（每平台各自构建、签名、公证、安装包体积），而它换来的只是「用本机编译器」这一项，性价比不成立。

**历史记录仍在**：`HANDOFF.md` §14（14.A–14.P）是已落地的实测记录，属事实档案，**随本文件冻结、不再更新**。原计划的五步推进顺序也在那一节，不在这里重复。

### 1.2 还没做的（原计划，已废）

不分优先级，只是把当时欠的账列全：

1. **Windows 实机实测 + 五处文案**（14.F 第 4 步）。五处 = `guide.html` / `guide.en.html` / `help.js` / `docs/使用手册.md` / `index.html` 的 `<noscript>`；一直刻意压着「等桌面版真能发布再动」。
2. **macOS 签名与公证**（Apple Developer 证书 + `notarytool`）。不签的后果是首次打开被 Gatekeeper 拦，要右键「打开」放行。
3. **Linux 全部**：打包配置、CI、实机。
4. **Rust 侧三个空缺**（14.B「尚未做」）：编译段没有看门狗（`clang++` 卡住会一直等）、没有编译产物缓存（对应 `compileCache`）、没有中途 kill 通路（取消只认「还没开始跑就被取消」）。
5. **两个诊断格式开关没对齐**：`-ferror-limit` / `-fmessage-length` 沙箱里有，桌面命令里没有。（`-w` 是两端一起加的，见 2026-10-18 那条，不在欠账里。）
6. **编辑器语法诊断在桌面端没有**（2026-10-19 新增的缺口）：桌面走系统 `clang++`，没有 wasm 工具链，`services/monaco/syntaxDiagnostics.js` 在那边按「工具链未就绪」静默跳过。要补得另加一条 Tauri 命令，参数口径必须与 `FRONTEND_ARGS` 一致，否则会出现「编辑器说没问题、编译却不过」。
7. **题解渲染器在桌面端装不上**（14.D 待决）：`mdRuntime.js` 靠 Cache Storage，桌面壳没有这个 API。要么 Rust 侧读本地文件，要么桌面端不提供题解预览——当时没拍。
8. **桌面端的 Python 解释器来源未定**：现在依赖系统 `python3`；随包带一个还是继续依赖系统，一直没决定。
9. **`dragDropEnabled: false` 没在真机拖过**（14.A）：无头探针验不了这一层，出包后需人工从系统拖一次文件确认。
10. **`export_*` 四条命令没在壳里人工验过**（14.O）：端到端探针够不着 Tauri，只在网页侧验了导入与打包下载。

### 1.3 重启的前提

先回答这三个问题，答不上来就别重启：

1. 网页版 / PWA 到底缺了什么，是**只有**桌面壳能给的吗？（目前唯一的答案是「系统编译器」，而它已经被编辑器内语法诊断覆盖了大半。）
2. 谁来承担每平台各自的构建、签名与公证？这是一条长期发布线，不是一次性投入。
3. Windows / Linux 的真机测试资源有没有？没有真机验证的出包等于没出。
