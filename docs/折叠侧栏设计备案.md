# 折叠侧栏设计备案

**是什么**：折叠态侧边栏（`panelVisible === false` 时顶替侧栏的那一条）的重设计**候选池**。

**与两份邻文档的分工**：`计划.md` 是「要做什么」的待办；`废案.md` 是「明确不做 / 已冻结」；
本文件是**同一个议题下的多个候选**——评审掉一个就从这里删一个：否决的写进 `废案.md`，
通过的按纪律写进 `HANDOFF.md`。这里不留历史。

2026-10-21 立。触发：用户认为现有「48px 通高竖条 / 50px 通宽横条、四枚 40×40 方块」可以重做。
五个方向与四个微创点最初来自一次外部建议，**落地口径一律以本文件为准**，不照抄外部表述。

## 0. 基线：现在的折叠态长什么样（评审时对照用）

| | 宽屏 1400×900 | 窄屏 390×844 |
| --- | --- | --- |
| 容器 | **48×888 竖条**（`flex: 0 0 48px`，圆角 10，**不描边**） | **378×50 通栏横条**（`flex: 0 0 auto`，`padding: 4px 8px`） |
| 位置 | 侧栏那一侧的最外侧（`order` 0 / 4） | 工作区上边或下边（`cp.narrowCollapseSide`，默认下） |
| 排列 | `space-between`：上簇＝两枚面板 + 若干固定格 + **簇尾的组件菜单**，下簇＝设置 | `row` + 居中 + `gap: 4px`，**固定格不摆**（组件菜单仍在上簇第 3 位） |
| 每格 | 40×40、圆角 10、图标**墨迹长边 21px**（多数见方；资源管理器＝自画矮盖方文件夹 21×18.6 零拉伸，评测样例保持扁宽 21×16.8）、`margin-left: 4px` | 同（`margin-left` 归零） |
| 侧栏本体 | 1px（basis 0% + `min-width: 1px` + 边框 0，内层 `visibility: hidden; opacity: 0`） | 高度 0（宽度仍 378） |
| 分隔条 | 仍在、可拖可单击 | `display: none` |
| 编辑器 | 1335 宽 | 378×778 |

**现状的五条硬约束**（任何方案都不能破）：

1. **侧栏必须留 ≥1px 的盒子**：View Transitions 靠旧快照补间，`display: none` 会让展开退化成「凭空出现」；0 面积在部分浏览器拿不到快照。
2. **48 / 40 / 4 都是设计值**：CSS 里的 px 构建期转 rem，随 `cp.uiScale` 变；JS 侧只有 `ACTIVITY_BAR_PX = 48` 一个副本。
3. **`is-active` 按格分、不按簇分**（2026-10-22 改）：面板格刻意不提亮（折叠态总有一个面板是「当前」，提亮等于常驻高亮），浮层格（组件 / 设置 / 固定格）提亮（语义是「这个界面开着」）。判据写在 `.activity-bar__item--menu` 上。**提亮只提一档**（同日加了 `--text-active`，夹在 `--text-dim` 与 `--text` 之间）：原来直接跳到 `--text`，与 hover 同亮度，而浮层一开就是常驻状态，等于常亮一档最亮。现在选中 = `#b5b5b5` / `#434343`（深 / 浅），hover 仍是 `--text`，两档分得开。
4. **方块定宽 40 + 固定 `margin-left: 4px`**：不用居中，因为栏伸缩时居中的方块会横移。4 = (48 − 40) / 2，栏 2026-10-22 去掉 1px 边框后内容盒就是 48，跟着从 3 改成 4。
5. **图标尺寸不写 `size="24"`**（2026-10-22 加）：各枚字形在各自 viewBox 里的外框差 50%，`ActivityBar.vue` 的 `iconOptics()` 按「墨迹长边 **21** CSS px」逐枚反算 `size` 并按 `vb/size` 反比补偿 `strokeWidth`。新增图标要往 `ICON_INK` 表里补**宽高两维**（`w` / `h`，viewBox 单位）。**21 是当天第四档、定稿**：20 比原来小一圈（原 `size="24"` 那套墨迹 17.9~23.9，被报回来）→ 24 又胀到原来最大那枚 → 22 落在中上区间 → 用户回头再收 1px 到 21。
6. **墨迹口径 = 长边 21px；「全栏见方」三轮试完才定**（2026-10-22 同日定稿）：只齐长边时宽窄差一截（文件墨迹 17.2 宽、用例 16.8 高）。第一版对 svg 做单向 scale（files ×1.222 / cases ×1.253），能齐但用户嫌变形；第二版**重画四枚字形**成方形外框，用户又嫌影响观感（files 页签太宽像一块板、cases 行距拉开后清单松散）；第三版资源管理器照抄 `folder`（20×17）靠拉伸补高，仍嫌丑；第四版单独画高成 20×20，比例还不对。**最终**（用户从五枚文件夹候选对照图里挑定）：`files` 用**自画矮盖方**（mac 风：盖沿压到 y=8、tab 顶 y=4.5，外框 20×17.5 天然近方），`ICON_INK` 标 `keep` 豁免拉伸，按近方原样上栏（墨迹 21×18.6，与候选图所见一致）；cases 保持 lucide 原版扁宽（同样 `keep`，墨迹 21×16.8）。flag / hourglass 的重画保留。`iconOptics()` 的拉伸机制仍在，但**别再顺手扩大适用面**。注意 files 是侧栏页签共用字形（`SidebarSwitcher` 的 size=16），换成文件夹后展开态页签 logo 也跟着变（实拍无违和）。

另有三条判据纪律：窄屏判据只有 `isNarrowLayout()` 一份（JS，给 `<html>` 挂 `is-narrow`），
样式一律写 `:where(html.is-narrow)`（不贡献特异性）；跨组件覆盖要自己挣特异性，别拼源码顺序；
折叠态容器在 `App.vue`，外观在 `ActivityBar.vue`，两处不要各存一份宽度。

## 1. 方向一 · 灵动胶囊（Floating Pill / Dock）

**要什么**：宽屏不再通高——48 宽、**按内容定高**的胶囊（4×40 + 间距 + 一条 20px 分割线 ≈ 184 高），贴左上或垂直居中；窄屏不再通宽——底部居中的悬浮 Dock，带毛玻璃。

**与现状的差别**：容器从「撑满主轴」变成「按内容定尺寸」，两簇靠分割线分组而不是 `space-between`。

**代价**

- `ActivityBar` 不能再当 flex 子项：现有的 `flex: 0 0 48px`、`space-between`、`order` 定位全部作废，要改成 `position: absolute`（或外层包一个不占位的壳）。**注意站内已有教训**：祖先链上一旦出现 `transform`，绝对定位会跳（`Sidebar.vue` 窄屏那段注释，2026-10-13），这条现在只是「谁再加带 transform 的动画它就复活」的预防性说明。
- **毛玻璃与今天的决定相反**：倒计时卡 2026-10-21 刚去掉毛玻璃、底色加厚到 0.94，理由是叠字发糊。要做毛玻璃得先问，且 `base.css` 两套主题都要给底。
- 通高改定高后，折叠态那一侧会空出一大片——这正是方向想要的效果，但要确认编辑器不会因此被「视觉上」误读为还有一条栏。

**待定**（v2 demo 里已各取一个值，仍需评审确认）：垂直居中还是贴左上（demo 取**居中**）；
窄屏 Dock 距底边多少（demo 取 33，为让开状态栏）；是否保持 48 宽（demo 保持 48，横过来由内容定宽 195）。

**状态**：2026-10-21 出了两版 demo（分支 `demo/fold-pill`，已推送、**未合入**），待评审。

- **v1**（`805a6e9`）：`align-self: center` 按内容定高（48×183，垂直居中）+ 20px 分组线，
  **没脱排版** —— 编辑器宽一格没多（1335 还是 1335），只换来观感。
- **v2**（分支头，当前这版）：**脱排版完整版** —— `position: absolute` + `top/bottom: 0` +
  `height: fit-content` + `margin-block: auto` 做垂直居中（**不用 transform**：横幅菜单是
  `position: fixed`，祖先带 transform 会让它跑偏，这正是本条「代价」点名的坑）；窄屏同时改成
  **悬浮 Dock**。

v2 读数（1400×900 / 768×1024 / 390×844，DSF 3，读 rect 与计算样式）：

| 档 | 胶囊 / Dock | 编辑器 |
|---|---|---|
| 宽屏左停靠 | 48×183 @ (6,359) | 1335 → **1383** |
| 宽屏右停靠 | 48×183 @ (1346,359) | 1383 |
| 768×1024 | 48×183 @ (6,421) | 703 → **751** |
| 窄屏贴底 | 195×50 @ (98,761)，两侧各 98 | 高 778 → **832** |
| 窄屏贴顶 | 195×50 @ (98,46) | 高 832 |

**遮挡（方向一真正的代价，v1 里不存在）**

- 宽屏：胶囊 6..54 与 Monaco 行号槽 12..80 相交 42px，与代码正文（`view-lines` 从 x=80 起）
  **相交 0px** —— 只盖住中间 183px 那几行的行号，一行代码都不挡。
- 窄屏：Dock 宽 195，横过来必然压正文（行号槽只有 ~50 宽）。已让开两条 UI 带，否则会盖住
  状态栏与页签栏：底 `33 = 6 + 1 + 22(.editor-pane__status) + 4`、顶 `46 = 6 + 36(editor-tabs) + 4`。
- 折叠态那条 12px 分隔条热区（`z-index: 5`）的中段被胶囊（`z-index: 6`）盖住，
  从胶囊上下两侧仍可拖 / 点。

**没做的**：毛玻璃默认不开（devtools 把根元素 `data-dock` 改成 `glass` 可对比，实测
`blur(14px)` + 72% 透明底生效）—— 理由仍是 10-21 去掉倒计时卡毛玻璃那条，胶囊浮在代码上
正是同一类「叠字」场景。

**验证**：⌘B 折 / 展各一次，`document.getAnimations()` 里有 `::view-transition-*`（VT 未退化）；
点胶囊「评测样例」→ 面板 1px → 554、胶囊隐藏；窄屏点 Dock 同理（211×832）；无 pageerror。

**怎么验**：1440 / 1024 / 768 三档量胶囊 rect 与编辑器可用宽；折叠 ↔ 展开的 VT 是否仍拍到旧快照（胶囊静态、无 transform 祖先）。

## 2. 方向二 · 边缘微缩手柄（Edge Handle / Peek）

**要什么**：折叠后只留 12–16px 热区或一个半透明把手；hover 时 48px 栏滑出；点面板可弹临时悬浮面板；Pin 才真正撑开布局。

**与现状的差别**：折叠态从「常驻一条栏」变成「常驻一个触发点」。

**代价（五个方向里最重）**

- **触屏没有 hover**：窄屏这条形态直接不成立。站内 2026-10-13 正是因为「折叠后只剩边界线、手指指不准」才把窄屏折叠态改成横条，这里会踩同一个坑 → 窄屏必须另给一套（点按出栏）。
- 「hover 滑出」等于浮层压在编辑器上，要处理指针离开、Esc、点外部关闭、焦点归还；站内没有现成的抽屉组件，得自绘（弹层一律自绘是站内口径）。
- Peek 面板（临时看样例）会与评测状态、运行入口纠缠，等于再造一个只读的 TestPanel。

**待定**：Peek 要不要做。建议先只做「hover 出栏 + 点击展开」，Peek 单列一条另评。

**怎么验**：宽屏 hover 进出 20 次的稳定性（不闪、不失焦）；窄屏纯点按路径；`prefers-reduced-motion` 下直切。

## 3. 方向三 · 状态外露（Status-Aware Bar）

**要什么**：折叠态的评测图标带状态——全绿 = AC、红 = WA、呼吸 = Running，或直接微缩 `2/3`；资源管理器图标带未保存圆点；上簇的 `is-active` 给一条 2×8 的次级指示条（hover 时加亮），表示「上次停留在此」。

**与现状的差别**：图标从「纯入口」变成「入口 + 读数」。

**代价**

- verdict 现在只活在评测面板的卡片里（`testCases` 在 `App.vue`，`applyPatch` 写回），折叠时整块 `hidden`。要在折叠态显示，取数点得**不依赖面板挂载**——`testCases` 本来就在 App，直接算即可，但「正在运行」还要一起看 `running` / `elapsed`。
- 呼吸灯是动画：站内 `base.css` 有全局 `* { animation-duration: 0.01ms }` 兜底（`prefers-reduced-motion`），不必另写，但**别用 JS 驱动**那类绕不过兜底的写法。
- 2×8 指示条在窄屏横排要改成 8×2，两个形态各写一次（宽度写 px，转 rem 后仍成立）。

**待定**：显示成圆点还是数字；Running 用呼吸还是静态色。

**状态**：2026-10-21 已出 demo —— 分支 `demo/fold-status-bar`（commit `d6f50d6`，已推送、**未合入**），待评审。
这一版做了：右下角 6px 圆点（tone 读 --ok / --fail / --err / --warn / --info）+ hover 时 title 带 `2/3`
+ 上簇 active 的 2×8 短条（左右停靠镜像、窄屏躺成 8×2 且随 fold-top/bottom 翻面）。
「数字形态」做成了可切换的第二分支（根上 `data-badge-style="dot"`，devtools 改 `count` 即见方块下缘的 `2/3`），
评审时可以两版并排比。**没做到**：真实判题跑出来的点 —— 无头里程序化塞样例会撞上回写/重建循环，跑不出结论；
圆点是被真实结构的数据驱动的，规则与 TestPanel 的 verdict 逐条对齐。

**怎么验**：造 3 条用例跑出 2 AC + 1 WA，折叠后读图标上的标记；再各看一遍 CE / 运行中 / 一条用例都没有。

## 4. 方向四 · 行为视觉解耦（Split Action）

**状态**：2026-10-22 **已采纳为正式版**，实现落在 `src/components/ActivityBar.vue` + `src/App.vue`（App 透传 `panelPosition` → 根上 `data-side`）。
落地的是：上簇 hover / 键盘聚焦浮出 4px chevron（随停靠侧镜像）+ 下簇默认 opacity 0.7；窄屏两条都不生效。demo 分支 `demo/fold-split-action`（`00f258f`）留在远端作参照。

⚠️ 2026-10-22 当日又撤回了两处（都在这条线落地之后）：
1. **`opacity: .7` 那一半撤掉** —— 「组件」那颗从下簇挪进上簇（当日先排第三格，随后又挪到簇尾）后，它成了上簇里唯一暗一格（竖列上 1 / 1 / 0.7），而这一档本来是给「上簇亮、下簇弱」的**簇**差异写的，参照系随位置变了。现在四格同亮，只留 chevron 这条。
2. **四枚图标的大小统一** —— 各枚字形在各自 viewBox 里的外框差得很远（实测 gear 22 / files 20 / timer 19 / cases 18 / clock 18 / grid 16，codeforces 是 24 且 viewBox 为 28 宽），并排就读成一大一小。按「墨迹长边 = **21** CSS px」逐枚反算 `size`，描边按 `vb/size` 反比补偿到视觉 1.9px。实现见 `ActivityBar.vue` 的 `iconOptics()`（只在本组件换算，不动 AppIcon 的 VIEWBOX）。**目标值当天试了四档**：20 比改之前小一圈（原 `size="24"` 那套墨迹是 17.9~23.9，用户报「比原来小了」）→ 24 对齐原来最大的设置那枚、又胀了一点 → 22 落在中上区间 → 用户回头再收 1px，**21 定稿**，各枚 size 落在 20.83~28.64。
3. **比赛 / 倒计时两枚字形换掉并加宽**（同一日第三处）—— 原来的 clock / timer 都是「圆表盘 + 指针」，缩到统一墨迹后只剩表冠能分辨，并排站着分不出来，换成立意不同的 `flag`（比赛）与 `hourglass`（倒计时）。换完发现**长边归一只管长边**：两枚都是竖长的，按 13 / 10 宽的字形画出来只剩 16.1 / 13.1 宽，比同栏 `files`（17.2）细一圈，竖条上像是「小一号」。所以保持高度不动、只在横向拉开字形（旗 13→16 宽、沙漏 10→15 宽），长边仍是 17.5 / 17 ⇒ `ICON_INK` 那两行**不用改**（size 恒为 26.19 / 26.95），实测宽度变成 **19.36 / 18.74**，落进既有区间。**新加图标也要这么看**：长边对齐之后还要比一下宽度，别只看长边。

**要什么**：上簇 hover 时方块朝工作区一侧浮出一个小 `›`（或图标右移 1–2px），暗示「点下去会把侧栏推开」；下簇默认图标 `opacity: .7`、hover 到 1，或两枚合并成一个紧凑槽，暗示「这是弹层工具」。

**与现状的差别**：纯视觉 + 微动效，**不动骨架**。

**代价**：几乎为零。两处要注意——`›` 的方向要随 `panelPosition`（左 / 右停靠）镜像；别在方块里加真元素（会改 40×40 的盒子与可点区），用 `::after`。

**怎么验**：左右停靠各读一次 `::after` 的位移方向；hover 前后方块 rect 不变（可点区不变）。

### 4.1 右键菜单：切停靠侧 + 固定组件（2026-10-22 落地，用户提出）

挂在图标栏整条 `nav` 上的 `contextmenu`，**只在「非窄屏 + 鼠标」下接管**（`isNarrowLayout()` 与
`isTouchPointer()` 都为假）；不满足时**不 `preventDefault`**，把系统菜单原样放走。
菜单本身复用 `ContextMenu.vue`（站内右键菜单的唯一渲染件），新增了可选的 `checked` 字段：

```
✓ 随机抽题              ← 勾选项：勾上 → 两枚面板格之后多一格，点它 = 打开该组件
  比赛
  倒计时
────────────
侧边栏移到右侧          ← 动作项，文案随当前停靠侧取反（写「点下去会发生什么」，不写「现在在哪」）
```

> 顺序 2026-10-22 按用户要求对调过一次：原先是动作项在最上、勾选项在下；现在勾选项在上、
> 动作项贴底。分隔线只跟「上面有勾选项」这一件事走 —— 一个组件都没装的时候菜单只剩动作项一条。

- **可固定列表按组件安装态过滤**（`available()`），一项都没有时连分隔线也不给。
- **固定格只在非窄屏渲染**，顺序 = 勾选顺序，位置在**两枚面板格之后、组件菜单格之前**（组件那颗 2026-10-22 挪到簇尾，固定格不再被它挡在前面）；`is-active` 走浮层格那一套（组件开着时提亮）。
- **目录与状态收在 `services/activityBarPins.js`**（`COMPONENT_GROUPS` / `pinnedComponents`），
  组件菜单 `ComponentsMenu.vue` 也从这里派生 —— 三处不许各抄一份表。
- **落盘键 `cp.activityBarPins`**（字符串数组）。读盘时按目录过滤，表里没有的 id 丢掉。

**为什么窄屏 / 触屏不做**：窄屏那条是 40px 高的通栏、贴着屏幕边，右键在那儿没有惯常心锚，
它自己的入口走底部与弹层那一套；触屏用户没有「右键」概念，长按也会派发 `contextmenu`，
真放行的话长按图标会冒出一份桌面菜单。

**怎么验**：宽屏右键 → 菜单顺序为「三项勾选 → 分隔线 → 动作项」；勾上 → 上簇多一格且刷新后还在；
点最后一项 → `data-side` 翻转、`cp.panelPosition` 跟着变、菜单文案变成反方向；390 宽与
`pointer: coarse` 下右键**不出**这份菜单；文件树 / 编辑区那些不带 `checked` 的菜单，条目的
`padding-left`（18.4px）、行高（28.03px）、`role` 与改动前逐项相同。

## 5. 方向五 · 零侧栏（顶栏融合）

**要什么**：折叠后彻底不留 48px，四个入口（或 1 个「展开侧栏」+ 一个评测状态胶囊）收进工作区左上角的横条。

**与现状的差别**：折叠态从「一条竖向栏」变成「编辑器页签栏左侧的一段」；宽窄屏两套形态合并成一套。

**代价（触及历史结论，先看再动）**

- 站内 2026-09-28 删掉了顶栏，现存的横条只有编辑器页签栏；`HANDOFF.md` §3 明写「**别再往这里加常驻按钮**——加了就要重新量五档宽度」，并给了 1680 / 560 / 414 / 375 / 320 五档的表。
- 页签 strip 是 `overflow-x: auto`，塞常驻按钮会挤窄它：320px 视口下 strip 只剩 132px。
- 好处是两套形态合一，`cp.narrowCollapseSide` 这个设置项可以退休（要给迁移路径，并撤掉设置菜单 / 设置面板里那一行）。

**状态**：2026-10-22 已出 demo —— 分支 `demo/fold-zero-rail`（commit `535171f`，已推送、**未合入**），待评审。
这一版只做**宽屏**折叠态：竖栏脱排版，四枚入口缩成 26×26 横排塞进页签栏左端（簇 124×35 @ 6,6），页签让出一个簇宽（左停靠 123 / 右停靠 128）；1440×900 下编辑器从 `[59,6,1375,888]` 变成 `[11,6,1423,888]` —— 左缘正好退掉那 48px。纯 CSS，判据只读 `html.is-narrow` 与 `.workspace.is-collapsed`，没加一行 JS。
**这一版没做**：窄屏（宽窄合一正是方向五的一半收益，但要重量 390 / 320）、右停靠镜像、折叠态分隔条让位（编辑器左 11 / 右 6 略不对称）；方向四那枚 chevron 在 26px 方块里会压住文件图标，本版把它关掉。

**待定**：只放一个「展开侧栏」还是四个入口全放；评测状态胶囊要不要占位；折叠后四枚入口留在左上角还是跟着停靠侧镜像。

**怎么验**：五档视口量 strip 宽、是否折行、是否横向溢出，对照 `HANDOFF.md` §3 那张表逐格比。demo 已按 1440 / 768 / 390 / 320 读过：宽屏 `docScrollWidth` 等于视口宽、首页签与图标簇右缘隔 5px；窄屏一条规则都没命中（底栏 378×50 / 308×50，与改动前逐项一致）。

## 6. 微创包（保留骨架，只打磨细节）

1. **折叠态右缘热区**：在 `ActivityBar` 朝工作区那条边做 hover 高亮 + 单击展开（现状折叠态只能拖分隔条或点图标，分隔条本身仍 `display: block` 停在原处）。注意别与「单击分隔条 = 折叠 / 展开」重复绑定同一次点击；`cursor` 用 `e-resize` 并配 `title`。
2. **展开 / 折叠的 FLIP**：现在 VT 是**整屏交叉淡化**（两栏的 `view-transition-name` 被临时摘掉，防快照拉伸）。要让四枚方块在「竖条 ↔ 页头胶囊」之间平滑位移，得单独给它们命名并放弃整屏淡化——这是**换动画策略**，不是加一条 transition。
3. **窄屏底栏加宽**：上簇两枚做成「图标 + 短文字」（文件 / 样例），下簇保持 40×40 靠右。窄屏页头已经退回纯图标（`compact`），这套只在折叠态出现，不与页头共用判据。现总宽 4×40 + 3×4 = 172，加宽后要重量 390 / 320 两档。

## 7. 怎么评审（每个 demo 一条流程）

- **一个方向一条分支**：`demo/fold-<slug>`，**不 push `main`**（`main` 就是部署分支）；分支本身可以推上去存档，评审完就删。
- 只改折叠态的外观与交互；`cp.*` 键名、VFS、判据函数都不动。要新增设置项，先回本文件记一条「待定」。
- 每个 demo 交付三样：**改动文件清单** / **实测读数**（1440、768、390、320 四档 × 两套主题）/ **反证**（撤掉改动、故障或原样复现）。
- 否决 → 结论与理由写进 `docs/废案.md`；通过 → 按纪律写进 `HANDOFF.md`，并从本文件删掉这一条。
- **建议顺序：四 → 三 → 一 → 二 → 五**。成本从低到高；一、二、五都可能推翻骨架，先确认低风险的那两条能不能满足大部分诉求。
- 进度（2026-10-22）：四**已采纳进 main**（`315a379`）；三 `demo/fold-status-bar`、一 `demo/fold-pill`、五 `demo/fold-zero-rail` 已出，均未合入；二未动。
