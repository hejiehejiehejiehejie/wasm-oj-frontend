# 装成 app 后的「返回」怎么接（2026-10-30，两版都已实施）

> 这份是**方案与决策记录**。现状、判据、实测读数以 `HANDOFF.md` §23 为准；
> 坑在 §5 坑 66。两边冲突时信 HANDOFF（那边跟着代码走）—— 本文只在「为什么这么选」上有价值。

## 1. 先定性：拦的不是系统事件，是后退历史

Web 没有 `backbutton` 这种东西（那是 Cordova / Capacitor 的私有事件）。PWA 里能做的是
**让历史里永远压着一条「哨兵」**，把用户那一次返回接成一次 `popstate`，再翻译成站内动作。

| 环境 | 用户怎么触发「返回」 | 能否接管 | 机制 |
| --- | --- | --- | --- |
| Android Chrome / Edge 装的 PWA | 底部返回键、左右边缘返回手势 | 能，但只能靠历史 | `pushState` + `popstate` |
| Android 国产浏览器（部分） | 同上 | 看内核，不保证 | 同上，需真机验 |
| iOS 添加到主屏 | **没有返回键**，也没有浏览器后退手势 | — | 不需要处理 |
| 桌面浏览器标签页 | `Alt+←`、鼠标侧键 | 能，但**不武装** | 保留原生语义 |
| Tauri 安卓壳 | 系统返回键 | 能，原生事件更彻底 | 冻结中，见 §9 |

判据只有一条：**只在独立窗口形态下武装**（`isAppWindow()`）。

```js
// manifest 是 display_override: ["fullscreen"]，安卓装出来匹配的是
// (display-mode: fullscreen) 而不是 standalone —— 三个都要列，漏一个就等于没生效
'(display-mode: standalone)' | '(display-mode: fullscreen)' | '(display-mode: minimal-ui)'
```

复核用口子：浏览器标签页里带 `?backstack=1` 也按「装成 app」跑一遍。没有这个口子，
这条功能在开发机上根本走不到。

## 2. 结构：一条哨兵 + 一条自己的栈

不选「开一层压一条 `pushState`」那种天然对齐的做法：一条 history 条目在刷新后会静默残留，
用户下次打开按返回，浏览器吃掉一层什么都不发生；点遮罩关闭时还得主动 `back()` 造一次伪后退。

```
services/backStack.js       模块级单例（与 notifications.js 同体例）

armBackStack()              启动武装一次：压哨兵、挂 popstate（**在 mount 之前**调）
pushBackLayer(onBack)       压一层「可关对象」，返回幂等的注销函数
watchBackLayer(source, fn)  把一个开 / 关型状态接到返回键上（入栈 / 出栈全自动）
```

`popstate` 里的顺序：

```js
try {
  const top = layers.pop()      // 先出栈：onBack 里翻标记会触发 watch 注销，已 pop 就找不到，幂等
  if (top) { top.onBack(); return }
  runFallbacks()                // 栈空才问兜底
} finally {
  ensureSentinel()              // 三条分支共用一个出口
}
```

**补哨兵**这一条是关键：它同时保证「还能继续关下一层」和「栈底那一发什么都不发生」。
收在 `finally` 里而不是各分支各写一遍，是让「返回键永不退 app」成为结构上的保证 ——
层里的 `onBack` 抛个异常就漏哨兵，漏了之后下一次返回真的退出 app，而且极难复现。

**栈底不退 app**（2026-10-30 改）：第一版是「栈底发一次提示、不再补哨兵，下一发由系统退出」，
用户驳回为「容易误触」。现在栈底同样补回哨兵，返回键在站内的终点就是「没反应」；
退 app 走系统默认路 —— Android 从最近任务划掉、桌面端关窗口。文案 `exitHint` 随之删除。

Web 上仍然做不到「再按一次才退」：哨兵要先被弹掉，那一发必然先进 `popstate`，没有第二发可数。

**`history.state` 不是空的**：`services/cloudEntry.js:90` 在里面放了 `cpCloudEntry`
（`/<handle>` 那套）。所以一律 `{ ...history.state, [SENTINEL]: true }`。

## 3. 返回键吃什么

| 序 | 对象 | 状态源 | 动作 | 挂在哪儿 |
| --- | --- | --- | --- | --- |
| 1 | 浮层 | 组件挂载 | `dismiss()` | `usePopoverLayer` 内部 |
| 2 | 提交确认 | `pendingSubmit` | `cancelSubmit()` | `App.vue` |
| 3 | 删除确认 | `pendingDelete.length` | `cancelDelete()` | `FileExplorer.vue` |
| 4 | 导出卡片（仅桌面壳会弹） | `pendingExport.length` | `cancelExport()` | `FileExplorer.vue` |
| 5 | Markdown 全屏 | `mdFullscreen` | `exitFullscreen()` | `EditorPane.vue` |
| 6 | 窄屏抽屉 | `isNarrowLayout() && panelVisible` | 收起（`togglePanel()`） | `App.vue` |
| 7 | 卸载扩展确认 | `pendingUninstall` | `cancelUninstall()` | `EditorSettingsPanel.vue` |
| 8 | 解绑确认 | `pendingUnbind` | `cancelUnbind()` | 同上 |
| 9 | 应用云端配置确认 | `cloudApplyHandle` | `cancelCloudApply()` | 同上 |
| 兜底 | CF 页内后退 | `props.active && canBack` | `goBack()` | `CfCodeforcesPanel.vue` |

前九类都是「有开有关」，进 LIFO 栈。**窄屏抽屉必须带 `isNarrowLayout()`**：宽窄屏共用同一个
`panelVisible`，不带就变成「宽屏按返回把一直开着的侧栏收掉」。

那个导出卡片是**二选一**（下载 / 写进本机目录），返回键只能退卡片、**不能替用户选**；
只有桌面壳才弹它，网页版点「导出」直接下载，所以在浏览器里验这条得先伪装成桌面壳。

「应用云端配置」那张卡**必须调它自己的 `cancelCloudApply()`**，不能只把 `cloudApplyHandle`
清空 —— 那个函数里还有 `clearPendingCloudHandle()` + `markCloudEntryHandled()`，少了这两句，
下次刷新会再问一遍（探针里就是照着这个断言验的）。

CF 页内后退是另一回事：它能连退多步、没有「打开」这个动作，是**路径**而不是**开关**，
所以走 `addBackFallback()`（不占栈位、只在栈空时问、可反复消费）。⚠️ 兜底不占栈位也就没人
帮它收窄时机，**它必须自己判「此刻该不该管」** —— CF 面板常驻挂载（`v-show` 保状态），
判据里那个 `props.active` 不能少。

实测叠层顺序（确认卡 + 全屏同时开）：返回一次只退全屏、确认卡还在；再返回才关确认卡。

## 4. 改动清单

| 文件 | 改了什么 |
| --- | --- |
| `src/services/backStack.js` | **新增**：哨兵、栈、`popstate`（`finally` 里补哨兵）、兜底层（`addBackFallback`） |
| `src/main.js` | `armBackStack()` 放在 `mount()` **之前**（setup 里的 `immediate` 可能要立刻注册第一层） |
| `src/composables/usePopoverLayer.js` | 挂载时 `pushBackLayer(dismiss)`；`dismiss` 与 `onBeforeUnmount` 两处幂等注销 |
| `src/App.vue` | `watchBackLayer(pendingSubmit, cancelSubmit)` + `watchBackLayer(窄屏抽屉, togglePanel)` |
| `src/components/FileExplorer.vue` | `watchBackLayer(pendingDelete, cancelDelete)` + `watchBackLayer(pendingExport, cancelExport)` |
| `src/components/EditorPane.vue` | `watchBackLayer(mdFullscreen, exitFullscreen)` |
| `src/components/EditorSettingsPanel.vue` | 三条：`watchBackLayer(pendingUninstall, cancelUninstall)` / `(pendingUnbind, cancelUnbind)` / `(cloudApplyHandle, cancelCloudApply)`，各配一个 `onBeforeUnmount` 注销 |
| `src/components/CfCodeforcesPanel.vue` | `addBackFallback(() => props.active && canBack && goBack())` |

**没有新增任何文案键**：曾经加过一条 `notifications.back.exitHint`（「再按一次返回即可退出」），
2026-10-30 栈底口径改了之后它描述的行为不复存在，已随那一轮删掉。`backStack.js` 也因此
不再 import `notify` / `t`。

**Esc 没动**：仍然是各浮层自己响应（`usePopoverLayer` 的捕获阶段），与返回键互不干扰。
`EditorPane.vue:503` 那段全屏 Esc 也没动 —— 它已经判了「Monaco 查找框 / 补全框开着就不抢」。

**既有行为变了两处**：① 窄屏下按返回先把抽屉收起来，而不是直接退 app；② **返回键在任何
情况下都不再退 app**（栈底补回哨兵）。两处都是 2026-10-30 用户口径，后一处是这一轮改的。

## 5. 坑

1. **补哨兵必须同步**。`await` / `setTimeout` / rAF 都会让用户看见后退动画。
2. **刷新后别重复压**：读 `history.state[SENTINEL]`，已经有就不压，否则每刷一次多一层。
3. **注销必须收在层内部**。浮层有四路关闭 + 外层 `v-if` 卸载，任何一条漏了注销，
   栈里就留一个幽灵条目，表现为「按了返回什么都没发生」。所以不许业务代码各自 `push`。
4. **`mdFullscreen` 是生效态**（`mdActive && mdView.fullscreen`），不是存档态 `mdView.fullscreen`。
   用存档态的话，在全屏里点开一个 `.cpp` 会留下一层永远关不掉的东西。
5. **验 `v-show` 的元素不能查 `querySelector`**：`.splitter` 在全屏时只是 `display: none`，
   元素还在 DOM 里。判据要用 `getClientRects().length`（探针第一版就栽在这里）。
6. **新建文件那行只选中主干**：`new.cpp` 的 `new` 被选中，`type('bbb.md')` 会拼成 `bbb.md.cpp`。
   探针里要先 `.select()` 再输入。
7. **宽窄屏共用 `cp.panelVisible`**：抽屉那一层的判据必须写成 `isNarrowLayout() && panelVisible`。
   少了前一半，宽屏上按返回会把常开的侧栏收掉 —— 那不是「退掉眼前这一件」。
8. **兜底层没有生命周期帮它收窄时机**：它不占栈位，栈空就来问一句。CF 面板是常驻挂载的
   （`v-show` 保状态），所以 `props.active` 必须写进判据，否则在代码页按返回会翻 CF 的内部页面。
   探针里专门做了这条对照（关掉 CF 页签、页内历史还在，按返回不能翻 CF 的页面）。

## 6. 实测（`/tmp/back-probe.mjs`、`/tmp/back-probe2.mjs`、`/tmp/noexit-probe.mjs`、`/tmp/exp-probe.mjs`，headless Chrome，除标注的一条外全部断言通过）

| 步骤 | 结果 |
| --- | --- |
| 启动 | `history.state.cpBackSentinel === true`，`history.length` 2 → 3 |
| 齿轮浮层 → 返回 | 菜单关闭、哨兵补回、URL 不变、页面未导航 |
| Esc 关浮层 → 返回 | 关的是下一层（没有幽灵条目） |
| 栈底连按 5 次 | 全部停在站内、一次 toast 都没弹、`history.length` 稳定 3 |
| 栈底之后开删除确认 | 哨兵仍在（`pushBackLayer` 里那句 `ensureSentinel` 此时是空转兜底） |
| 删除确认 → 返回 | 确认框关闭，**不是**确认删除 |
| Markdown 全屏 → 返回 | `mdFullscreen` 变 false、布局恢复、页面未导航 |
| 确认卡 + 全屏叠着 → 返回一次 | 只退全屏，确认卡仍在 |
| 一直按到底 | **仍在站内**，不导航、不白屏（2026-10-30 起；之前是离开站点） |
| 浏览器标签页（无 `?backstack=1`） | `history.state` 仍是 `null`、`history.length` 仍是 2 —— 完全没武装 |
| 窄屏 560×900 → 返回 | 抽屉收起、哨兵补回；再按一次 → 仍在站内、什么都不发生 |
| 窄屏 + 删除确认叠着 → 返回三次 | 第一次只关确认框、第二次关抽屉、第三次起什么都不发生 —— 常驻栈底那层不会被顺手带走 |
| 宽屏 1400×980 → 返回 | 侧栏**不**收起（对照，证明没接错判据） |
| CF 切「赛程」→ 返回 | 回到「抽题」、后退钮变灰、不弹提示、哨兵补回；再按一次 → 仍在站内 |
| CF 页签关掉、页内历史还在 → 返回 | 不走 CF 内部页面，落到「什么都不发生」 |
| 假兜底：前一个抛错 | 不连累后一个、不丢哨兵（`onPopState` 的 `finally` 兜住） |
| 假兜底：连消费两次 / 注销后 | 可反复消费；注销之后回到「什么都不发生」；两种情况哨兵都在 |
| 导出卡片 → 返回（伪装成桌面壳才弹得出来） | 卡片关掉，**没有替你选**下载还是落盘；Esc 关掉后再按返回仍在站内 |
| 解绑确认 → 返回 | 卡片关掉，`cp.cloudAccount` 里的 handle 还在（是取消，不是解绑） |
| 应用云端配置 → 返回 | 卡片关掉，`pendingCloudHandle` 被清空 —— 确实走了 `cancelCloudApply` |
| 卸载确认 | **没做浏览器实测**：要在运行时真 ready（76MB 工具链）时才开得了这张卡 |

`npm run verify` 与既有基线一致（**B/C/D/F 绿、A/E/G/H 红**），无新增回归；
`npx vite build --outDir /tmp/...` 通过。

### 6.1 已知浏览器缺陷：Firefox 安卓安装窗口不消费哨兵（2026-11-01，只记录不改行为）

Firefox 安卓把本站「安装」成独立窗口后，在**首页**按一次系统返回 → 整屏变成纯深的空窗口（没有任何站内
界面）；再按一次 → 退出 app。与上表「一直按到底仍在站内」正相反。

- 那一发**不进历史**：到达页面的是 `pagehide` 而不是 `popstate`，文档被卸载、空窗口留下（Mozilla
  Bugzilla **2070832**）。§2 那条哨兵因此没有机会被消费 —— 不是判据漏档，也不是哨兵没补：安装产物里
  `(display-mode: standalone)` 为真（设置 › 应用显示「已安装」），`armBackStack()` 确实武装过。
- 空窗口的深色是 Firefox 按 manifest 的 `background_color`（`#1c1c1c`）涂的，不是站内画的页。
- 页面侧无解（Web 没有返回键事件、也拦不住卸载）；`pagehide` 里 `location.reload()` 只会变成「按一次
  重启一次」。Chrome 安卓同一套机制实测正常。
- **已定，不改行为**（2026-11-01 用户口径）：判据、`pushState` 时机、manifest 一律不动。用户侧绕路是把
  Firefox 安卓当普通标签页用（不安装），或改用 Chrome 安装。详见 `HANDOFF.md` §23.7 与 §5 坑 71。

## 7. 不做的

- **关视图页签**（设置 / 抽题 / Codeforces）：页签是并行工作区，不是导航栈。
- **倒计时卡、toast 通知**：不是用户「打开」的层，关掉是损失。
- **iOS 特判**：没有返回键，机制空转，不加分支。
- **`cp.*` 新键**：这套东西不持久化。

## 8. 剩下的

1. **Esc 的口径**：仍是各浮层各自响应，两个浮层同时开着会一起关；改成「只关最上层」要单独一轮。
2. **「地址里这个 handle 云端没有配置」那张提示卡**（`cloudEntryMissingHandle`）：没接 ——
   它只是句一次性提示、没有选项要选；要接就是同一处再补一行。
3. **CF 页内退到底之后再按返回**：**已定，不改**（2026-10-30 用户口径）。现在落到栈底那条
   「什么都不发生」，不改成「退出 CF 页签」—— 那一步会丢页内状态。

## 9. 安卓壳（冻结，只记方向）

解冻后可以做得更彻底：返回键是原生事件，能在它派发成「导航」之前接住，连哨兵都不需要。
届时两侧共用同一个 `backStack` 的层注册表，只在 `armBackStack()` 里换数据来源
（`popstate` → 原生返回键回调）。
