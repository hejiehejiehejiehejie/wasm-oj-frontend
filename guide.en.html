1. What is this site?

  • Write, compile, run and judge code in your browser.
  • The local sandbox supports C++ and Python 3.
  • Compiling and running both happen on your device. Your code never leaves this machine.
  • No sign-up, no login.
  • You can install it as a standalone window app and use it offline.

Default layout: sidebar on the left, editor on the right.

The sidebar holds two panels: Explorer and Test cases.

2. How do I run code in the browser?

  1. Download the local runtime. Click the gear icon in the sidebar header, open the Settings tab, then go to Local runtime.
  2. Click Download next to C++ or Python 3. Roughly 50MB and 24MB, downloaded once each.
  3. Wait for the button to read Ready. The current stage is announced while it downloads.
  4. Make sure the engine under Judge is Local WASM sandbox. That is the default for new visitors, and it needs no service URL.
  5. Press ⌘/Ctrl + Enter, or click the ▶ in the footer of the Test cases panel.

The sidebar expands automatically before a run and switches to Test cases.

Need the space back? The Ready row has Uninstall on the right.

  • The runtime is downloaded once, and later page loads hit the cache.
  • One download is enough to run offline: the editor, the test cases and the sandbox all live on your machine.
  • Clear your browser data and you will have to download it again.
  • Python is not compiled — it runs straight in the interpreter.
  • C++ compiles only the file you have open, and local headers are not included.
  • Python can import modules from the same folder.
  • File reads and writes inside the sandbox stay in memory. They are never written back to your workspace.

3. Which judge engine should I pick?

Switch it under Settings › Judge.

Engine Where it runs Needs a service URL? Needs the network?
Local WASM sandbox (default) Your own browser; supports C++ and Python 3 No — it is a built-in engine Downloads the runtime once, then works offline
Piston A judge service you host yourself Yes Yes
Judge0 A judge service you host yourself Yes Yes
Self-test (does not run code) A local demo No No

A remote engine means hosting the service yourself and entering its URL under Judge.

  • Once you switch to Piston or Judge0, your code is sent to the URL you entered.
  • Self-test does not run code. It echoes the standard input back, for exercising the UI.

4. How fast is it in the browser?

There is no single scaling factor.

These are measurements: Apple M5, headless Chrome.

Both sides run with -O2.

The sandbox uses clang 8.0.1; the native column uses the system clang.

The sandbox column is the run phase — the same thing the card timing measures.

Case Sandbox run phase Native Ratio
Pure compute, 5×10⁷ rounds of xorshift 132 ms 74.4 ms 1.77×
Sequential access, 8×10⁶ ints 26 ms 7.4 ms 3.51×
Sorting 500k numbers 60 ms 11.8 ms 5.08×
Sorting 2M numbers 247 ms 36.7 ms 6.73×
  • The ratio climbs with memory density, from about 1.8× to about 6.7×.
  • The more a workload leans on memory bandwidth, the more it slows down.
  • The ratio cannot be extrapolated. Do not use 5× to guess at other code.
  • Five samples spread over ≤3 ms, and the output matched native byte for byte. This is not noise.
  • Both columns include startup cost: process launch on the native side, WASI instantiation in the sandbox.
  • The shorter the run, the more those two constants flatten the ratio.
  • On a different machine, both the absolute times and the ratios change.

Why doesn't the empty-program comparison count?

The empty-program comparison is an illusion.

That 4.4 ms on the native side is all process startup.

The 3.0 ms in the sandbox is WASI instantiation.

Neither number contains any computation, so comparing them means nothing.

For a real comparison, look only at the rows that actually compute.

5. How do I import a problem?

Use the CC for Web extension distributed from this site.

  1. Open Settings › Browser extension and click Download.
  2. Unzip the downloaded archive.
  3. Open chrome://extensions in the address bar and turn on Developer mode in the top right.
  4. Click Load unpacked and select the folder you just unzipped.
  5. Back on this site, click Check again in that group. The status will show the version.
  6. Open any problem page on an online judge and click the extension icon in the browser toolbar.
  • The problem lands in <year-month>/<OJ>/未分类/, under the workspace root.
  • The samples replace the contents of the Test cases panel wholesale. No manual copying.
  • The code file holds a single line, // your code here. The solution is yours to write.
  • Difficulty is yours to fill in: right-click the file › Problem info.
  • Re-importing the same problem only refreshes the samples and metadata. Not a character of your solution is touched.
  • Problems are identified by Problem URL, not by file name.
  • This site has to be open for the extension to deliver anything.
  • The extension is not in any extension store, so this is the only way to install it.

6. How are verdicts and the time limit calculated?

One card per test case, holding the input and the expected output.

The actual-output field below is read-only, with a copy button in its top right.

The blank strip in the middle of a card is the “run this case only” button.

Verdict Meaning
AC The program finished normally and its output matches the expected output
WA The program finished normally and its output differs from the expected output
CE Compilation failed
TLE The run exceeded the current time limit
RE Runtime error — the program exited abnormally
ERR An environment problem such as an unreachable judge service. Not a problem with your code

After you change your code or the input, the previous verdict is marked Result stale.

What exactly do the time limit and the elapsed time measure?

  • The run phase only — not compilation, not queueing.
  • The run phase includes a fixed sandbox startup cost of a few milliseconds.
  • The card timing measures the same thing. No timing is shown if the program never got to run.
  • The panel header shows the slowest case of the current run.
  • Default: 1 second. To change it: Settings › Judge › Time limit — 1 / 2 / 5 / 10 seconds.
  • A time limit stored on the problem takes priority: right-click the file › Problem info › Time limit (s).
  • Python gets an extra 0.5 s of startup allowance, so a TLE can arrive up to half a second late.

7. How do I use the file tree?

  1. The header has two buttons: New file and New folder.
  2. The new entry goes into whichever node is currently focused in the tree.
  3. To place it somewhere specific: right-click that folder › New file / New folder.
  4. Type a name and press Enter. Only the stem is selected, so you do not have to retype the extension.

Right-clicking a file also offers Rename and Delete.

What goes into Problem info?

  • Five fields: Problem URL, Judge, Difficulty, Date and Time limit (s).
  • Difficulty follows the judge — the two scales are not interchangeable.
  • Codeforces and AtCoder use the 800–3500 rating band.
  • Luogu uses its eight official levels.
  • NowCoder, LeetCode and Other take free text.
  • Changing the judge clears the difficulty, so a mismatched value cannot linger.

Imported problems are layered as <year-month>/<OJ>/<difficulty> directly under the workspace root, with the problem title as the file name.

Problem info and captured samples live on the code file itself, so nothing extra shows up in the tree. The importing extension creates the 未分类 folder under its Chinese name in either interface language.

How do I write notes (Markdown / LaTeX)?

Notes are just a .md file: click New file in the header, rename it to “notes.md” and press Enter. Open it and a toolbar appears above the editor, with the word count and the view buttons at its right end.

  1. 14 toolbar buttons: bold, italic, strikethrough, inline code, heading, quote, bullet list, numbered list, code block, link, image, formula, table and horizontal rule. Hover one to see its shortcut — bold is Mod + B.
  2. The three view buttons at the right end (editor only / split / preview only) switch the layout at any time, and Mod + \ cycles through them; the button next to them gives the editor the whole window, and Esc leaves it.
  3. Write formulas as $inline$ and $$on their own line$$; the preview renders them as LaTeX.

The preview needs a one-time renderer download (marked + KaTeX, about 578KB) — like the local runtime, it is downloaded once and can be uninstalled at any time.

Notes are not judged: opening a .md greys out the run button, and Mod + Enter will not start a compilation.

On macOS Mod is ⌘; on every other platform it is Ctrl.

Swap the sidebar side Mod + Shift + B

  • These also fire while the editor has focus, and they win over the editor's own bindings.
  • To rebind: Settings › Shortcuts, click the field on the right, then press the new combination.
  • Press Delete to clear a binding, Esc to cancel recording.
  • A combination that clashes with a browser shortcut is rejected, with the reason given.
  • Restore defaults puts the whole table above back.
  • Once you change them, the run hint in the editor's status bar follows.

9. How do I tweak the interface?

  1. Switch panels: click the pill switch on the left of the sidebar header.
  2. Toggle the settings tab: click the gear in that header.
  3. Collapse the sidebar: double-click the divider between the two columns.
  4. You can also drag the divider to the edge; drag it back out to expand again.
  5. Move it to the other side: Settings › Appearance › Sidebar position.
  6. Scale the interface: Settings › Appearance › Interface scale — 100% by default.
  7. Change the colours: Settings › Appearance › Theme — dark / light.

Collapsing only hides the sidebar. Neither the test cases nor the expanded folders are lost.

Keyboard: focus the divider with Tab, then nudge the width with ← / →.

On touch screens the divider's hit area widens on its own, which makes it easier to grab.

It only collapses at the very edge and only expands 60px away from it — the two thresholds are deliberately staggered.

10. How do I install it and use it offline?

  1. Open Settings › App.
  2. The Install button only lights up once the browser considers the site installable.
  3. Click Install and confirm the prompt.
  4. After that, opening it from the desktop or home-screen icon gives you a standalone window with no address bar.
  • Once it is installed the button reads Installed and the prompt stops appearing.
  • Safari on iPhone / iPad has no such button — use Share → Add to Home Screen instead.
  • Toolchains are cached on demand: a language only runs offline once you have used it at least once.
  • Offline, the editor, the test cases and the local sandbox keep working. Only Piston and Judge0 stop.

11. Common questions

Does my code get uploaded to a server?

With the local sandbox, no. Your code never leaves this device.

Switch to Piston or Judge0 and your code is sent to the URL you entered.

Do I need to be online?

Only the first time, to download the runtime — about 50MB.

After that it stays in the cache and works with no network.

Clear your browser data and you will have to download it again.

Which languages are supported?

The local sandbox supports C++ and Python 3.

For anything else, switch to Piston or Judge0.

What you get depends on the service you connect to.

Why is the first run so much slower?

The runtime is downloaded on the first run.

After that, the first case of every new piece of code pays the compilation cost once.

Running several cases against the same code compiles it only once.

A precompiled STL header is built in the background during idle time and never blocks you.

It covers only the 5 most common standard library headers. A failure to build it does not affect normal compilation.

Why doesn't the timing match other judges?

The timing here covers the run phase only, excluding compilation and queueing.

So the numbers come out smaller than on platforms that report total time.

Different engines and different machines are not directly comparable either.

Where is my data stored?

Preferences, drafts, test cases and the column split live in localStorage.

The file tree and the file contents live in IndexedDB.

The precompiled header lives in IndexedDB too.

All of it is confined to this browser on this device. Clearing your browser data clears it as well.

Are cloud-synced settings public?

Yes. Reading the cloud copy needs no sign-in — append your Codeforces handle to the site URL, e.g. https://www.998244353.best/he-jie, to fetch it.

So clicking Upload local settings means you agree to make this configuration public.

Only preference keys are uploaded: theme, shortcuts, UI scale, sidebar side, column split, run time limit and the like.

The judge URL you entered, hand-written test cases, the file tree and file contents are never uploaded.

What if the extension cannot grab the problem?

First make sure this site is open in a tab.

Then check whether Browser extension shows a version number.

If it does not, click Check again; if that still fails, reload this page.

A reloaded extension loses touch with a page that has not been refreshed since.
